# ERC-8004: Trustless Agents

Source: https://eips.ethereum.org/EIPS/eip-8004
Fetched: 2026-05-13

## Abstract

ERC-8004 proposes a blockchain-based protocol enabling agent discovery, selection, and interaction across organizational boundaries without pre-existing trust relationships. The specification introduces "pluggable and tiered trust models with security proportional to value at risk," supporting reputation systems, cryptoeconomic validation, zero-knowledge ML proofs, and trusted execution environment oracles.

## Core Motivation

The protocol addresses a gap in existing agent communication frameworks. While Model Context Protocol (MCP) and Agent2Agent (A2A) handle capability advertisement and task orchestration, they lack standardized mechanisms for agent discovery and trustworthiness assessment. ERC-8004 provides three lightweight registries deployable on Layer 2 networks or mainnet as chain-specific singletons.

## Three Registry Components

### 1. Identity Registry

Built on ERC-721 with URIStorage extension — agents are immediately browsable and transferable with NFT-compliant apps.

Global Agent Identification: `{namespace}:{chainId}:{identityRegistry}` (e.g., `eip155:1:0x742...`)
Each agent receives a unique `agentId` (ERC-721 tokenId).

Agent Registration File (resolved via agentURI):

```json
{
  "type": "https://eips.ethereum.org/EIPS/eip-8004#registration-v1",
  "name": "agentName",
  "description": "Natural language description including capabilities, pricing, interaction methods",
  "image": "image_url",
  "services": [
    {
      "name": "A2A",
      "endpoint": "agent_card_url",
      "version": "0.3.0"
    }
  ],
  "x402Support": false,
  "active": true,
  "registrations": [{
    "agentId": 22,
    "agentRegistry": "{namespace}:{chainId}:{identityRegistry}"
  }],
  "supportedTrust": ["reputation", "crypto-economic", "tee-attestation"]
}
```

Key functions:
- `register(string agentURI, MetadataEntry[] calldata metadata)` — Mint new agent
- `setAgentURI(uint256 agentId, string calldata newURI)` — Update registration file
- `setMetadata(uint256 agentId, string metadataKey, bytes metadataValue)` — Store optional metadata on-chain
- `setAgentWallet(uint256 agentId, address newWallet, uint256 deadline, bytes signature)` — Designate payment receiver (requires EIP-712 or ERC-1271 signature verification)

The reserved `agentWallet` metadata key automatically resets to zero address upon token transfer, requiring new owner verification before re-assignment.

### 2. Reputation Registry

Standardized feedback mechanisms for agent evaluation.

Feedback structure:
- Required: `value` (int128), `valueDecimals` (uint8, 0-18)
- Optional: `tag1`, `tag2`, `endpoint`, `feedbackURI`, `feedbackHash`

```solidity
function giveFeedback(
  uint256 agentId,
  int128 value,
  uint8 valueDecimals,
  string calldata tag1,
  string calldata tag2,
  string calldata endpoint,
  string calldata feedbackURI,
  bytes32 feedbackHash
) external
```

Feedback examples:

| Tag | Measurement | Example | Value | Decimals |
|-----|-------------|---------|-------|----------|
| `starred` | Quality rating (0-100) | 87/100 | 87 | 0 |
| `uptime` | Endpoint uptime (%) | 99.77% | 9977 | 2 |
| `successRate` | Endpoint success rate (%) | 89% | 89 | 0 |
| `tradingYield` | Yield (with tag2 timeframe) | -3.2% | -32 | 1 |

Off-chain feedback file (referenced by feedbackURI):

```json
{
  "agentRegistry": "eip155:1:{identityRegistry}",
  "agentId": 22,
  "clientAddress": "eip155:1:{clientAddress}",
  "createdAt": "2025-09-23T12:00:00Z",
  "value": 100,
  "valueDecimals": 0,
  "tag1": "foo",
  "tag2": "bar",
  "mcp": { "tool": "ToolName" },
  "a2a": {
    "skills": ["skill_identifiers"],
    "contextId": "context_id",
    "taskId": "task_id"
  },
  "proofOfPayment": {
    "fromAddress": "0x00...",
    "toAddress": "0x00...",
    "chainId": "1",
    "txHash": "0x00..."
  }
}
```

Other functions:
- `revokeFeedback(uint256 agentId, uint64 feedbackIndex)`
- `appendResponse(uint256 agentId, address clientAddress, uint64 feedbackIndex, string responseURI, bytes32 responseHash)`
- `getSummary(uint256 agentId, address[] clientAddresses, string tag1, string tag2)` — Aggregated reputation (non-empty clientAddresses mitigates Sybil)
- `readFeedback()`, `readAllFeedback()`
- `getClients(uint256 agentId)`

### 3. Validation Registry

Independent verification of agent outputs via stake-secured re-execution, zkML proofs, or TEE oracles.

```solidity
function validationRequest(
  address validatorAddress,
  uint256 agentId,
  string requestURI,
  bytes32 requestHash
) external

function validationResponse(
  bytes32 requestHash,
  uint8 response,           // 0-100 scale (binary or spectrum)
  string responseURI,
  bytes32 responseHash,
  string tag
) external
```

Multiple responses per requestHash enable progressive validation states ("soft finality" → "hard finality"). Only original validatorAddress may respond.

Other functions:
- `getValidationStatus(bytes32 requestHash)` — Returns validator, agentId, response, evidence hash, tag, timestamp
- `getSummary(uint256 agentId, address[] validatorAddresses, string tag)`
- `getAgentValidations(uint256 agentId)`
- `getValidatorRequests(address validatorAddress)`

## Security Considerations

- Sybil mitigation via reviewer filtering — protocol surfaces signals with consistent schema; reputation aggregation builds on top
- On-chain pointers/hashes are immutable, preserving audit trail
- Validator incentives are managed by specific validation protocols (out of scope)
- Cryptography ensures registration ↔ on-chain correspondence but cannot guarantee advertised functionality is operational/non-malicious — the three trust models (reputation, validation, attestation) address this gap

## Technical Dependencies

- EIP-155 (chain identifiers)
- EIP-712 (typed data signing)
- EIP-721 (NFT)
- EIP-1271 (smart contract signature validation)

## Implementation Notes

- Chain-specific singletons
- Agents can register on multiple chains simultaneously
- Base64-encoded `data:` URIs support fully on-chain metadata
- IPFS endpoints for feedback files enable subgraph indexing
- EIP-7702 can sponsor feedback submission for frictionless client interaction
